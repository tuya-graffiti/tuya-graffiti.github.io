4 铁路调度通信网

一、核心内容总结

1. 干线调度通信网

  • 网络组成：铁道部 Hicom 382 为汇接中心，各铁路局 Hicom 372 通过 2M 数字中继连接，相邻铁路局设直达路由，构成复合星形网。
  • 编号与呼叫：全路统一五位码（ABCDE，AB = 局向号，CDE = 用户号），调度台单键直呼，网内用户直拨五位码，调度员可强插、全呼 / 组呼。
  • 同步：主从同步，铁道部 SPC 为主时钟，Hicom 382 为第一从时钟（双备份），铁路局 Hicom 372 从第一从时钟提取时钟，故障时启用自身时钟（精度 ±1×10⁻⁶）。
  • 接口与信令：局间用 30B+D 数字接口，CorNET 共路信令（覆盖 Q.930/Q.931 标准），支持遇忙转移、会议电话、强拆等调度功能。

2. 局线调度通信网（三种组网方式）

组网方式 结构 优点 缺点
用户线方式 铁路局 Hicom 372 直接放号到站段（PCM + 环路设备） 简单 占干调端口 / 通道，灵活性差，难延伸至中间站
中继线方式一 铁路局 Hicom 372 + 站段 Hicom 315，2M 中继星形组网 网管 / 信令统一 难延伸至中间站，不兼容模拟区段，浪费区段设备
中继线方式二 铁路局专用通信主系统 + 站段区段数字设备，2M 中继星形组网 兼容模拟区段，利用既有设备 需信令转换（局 - 区段用 DSS1，区段 - 中间站用内部信令）
  • 编号：五位码（同干线），中间站模拟用户需经局调台转接。
  • 同步：铁路局局调交换机为第一从时钟（从干调 Hicom 372 提取），站段交换机从第一从时钟同步。

3. 区段调度通信网

  • 核心特点：①数字共线型（调度员 - 车站值班员一点对多点，复用时隙）；②2M 自愈环（主用 + 备用 2M，断纤后迂回）。
  • 组网关键：
    • 自愈环容量：稳定串接 50-64 个分系统，实际按 1-2 个行车调度区段组网（避免过长影响可靠性）。
    • 特殊场景处理：
      • 枢纽列调：星型汇接（A/B 方向纳入主干环，C 方向自建支环，D 方向模拟接入）。
      • 分支线：模拟分支用模调接口，数字分支自建支环接入主干环。
      • 无 ONU 站：邻近站延伸 2B+D 接口，或用数字倍增器（区间实回线主备）。
  • 时隙分配：PCM 30/32 帧，TS₀（同步）、TS₁₆（信令），可用 26 个时隙；信令占 TS₂₈-TS₃₁（3-4 个），调度业务（行调 / 货调等）各占 1 个共线时隙，站间业务占 2-3 个时隙（分段复用）。

二、课后题答案（复习思考题）

  1. 局线调度网组网方式及优缺点答：三种方式：
    • 用户线方式：优点是简单；缺点是占用干调端口和长途通道，灵活性差，难延伸至中间站。
    • 中继线方式一（Hicom 系列）：优点是网管和信令统一；缺点是难延伸至中间站，不兼容模拟区段，浪费既有区段设备。
    • 中继线方式二（专用通信 + 区段设备）：优点是兼容模拟区段，利用既有设备，灵活延伸至中间站；缺点是需信令转换（局 - 区段用 DSS1，区段 - 中间站用内部信令）。
  2. 区段网 2M 自愈环优点答：①断纤自愈：任意点断裂后，通过备用 2M 迂回，不中断通信；②双重保护：即使传输网故障，区段自愈环仍可独立保障调度业务；③提升可靠性：配合设备 1+1 热备份，满足铁路调度 “不间断” 需求；④简化维护：无需人工倒接，自动恢复。
  3. 区段网 PCM 30/32 时隙分配答：①TS₀：同步时隙（偶帧传帧同步码 0011011，奇帧传失步告警 A₁）；②TS₁₆：标志信号时隙（F₀帧传复帧同步码 0000，F₁-F₁₅帧传 30 路话路信令）；③可用话路时隙：TS₁-TS₁₅、TS₁₇-TS₃₁（共 30 个）；④信令控制时隙：占用 TS₂₈-TS₃₁（3-4 个）；⑤业务时隙：行调 / 货调 / 电调 / 无线列调各占 1 个共线时隙，站间业务占 2-3 个时隙（分段复用），剩余时隙可扩展公务电话、应急通信等。

第五章 DMIS 系统

一、核心内容总结

1. DMIS 系统概述

  • 定义：铁路运输调度指挥管理信息系统（Dispatch Management Information System），替代传统手工调度，实现 “三级（部 / 局 / 站段）分散控制、集中管理”。
  • 发展：1996 年立项，“九五” 一期建 545 个车站采集网，“十五” 二期全面推广，核心是实时采集 / 处理列车运行信息，支撑调度自动化。
  • 特点：高技术性（计算机 / 网络 / 多媒体）、封闭网络（闭环控制）、独立性（专注行车指挥）、实时性（信息捕捉 - 处理 - 显示无延迟）、高可靠性（容错设计）、安全性（故障 - 安全、防病毒）。

2. DMIS 系统结构

  • 总体结构：铁道部 - 铁路局 - 站段三级广域网，各层级以交换机为核心组建局域网，路由器互连。
  • 各层级硬件：
    • 铁道部：高性能服务器、工作站、大屏投影，接收全路实时信息。
    • 铁路局：双服务器 + 磁盘阵列（集群，负载均衡 / 热备）、双交换机（双网冗余）、行调台、网管工作站、大屏投影。
    • 站段：服务器、行调台、路由器，连接基层采集点。
    • 基层网：DMIS 分机（信息采集 / 控制）、电务监测机、车务终端（邻站显示 / 调度命令接收）、路由器 / 集线器。

3. DMIS 系统功能与作用

  • 铁道部：宏观监视全路列车运行（正点率 / 密度）、重点列车追踪、分界口统计。
  • 铁路局：
    1. 宏观显示：正点率（客车＞98%/80-98%/＜90% 三色显示）、列车密度（图定利用率＞90%/80-90%/＜80% 三色）。
    2. 实时监视：枢纽 / 编组站 / 客站 / 分界口列车位置、信号状态。
    3. 运行图管理：自动绘制计划 / 实际运行图，支持打印。
    4. 分界口管理：交接列车统计、正晚点报告、历史查询。
    5. 调度命令下达：通过网络直传车站，替代人工电话。
  • 站段：实时监视辖区列车 / 信号状态、车次号管理（人工输入 + 无线校核）、自动报点、运行图自动生成、调度命令接收 / 打印。
  • 基层网：信息采集（列车到发 / 信号状态）、车次号输入 / 修正、无线车次号校核、站间透明显示。

4. 计算机辅助行车调度系统（CAD）

  • 目的：减少调度员事务性工作（收点 / 画图）、提供计划调整决策支持、自动统计列车运行指标。
  • 结构：实际运行图管理（存储 / 查询 / 打印）、列车运行调整（自动 / 手动调整 4h 货运 / 8h 客运计划）、运行统计（正晚点 / 平均速度）、共享动态数据库（支撑多区段协调）。

5. 调度监督与调度集中系统

  • 定义：利用遥测 / 遥信 / 遥控监控车站信号和列车运行，调度集中在监督基础上增加 “控制” 功能。
  • 功能：列车状态显示、车次跟踪、行车计划管理、区间信息采集、控制（人工 / 存储 / 自动控制）。
  • 控制方式：
    • 人工控制：实时输入命令，无排队，适合特殊情况。
    • 存储控制：预先输入命令序列，系统自动检查时机执行（车流稳定时用）。
    • 自动控制：按阶段计划自动办理进路，依赖计划系统。
    • 站控 / 遥控：车站值班员 / 调度员控制，需授权切换。

二、课后题答案（复习思考题）

  1. DMIS 系统的特点答：①高技术性：融合计算机、网络、多媒体、远程控制技术；②封闭网络：信息采集 - 处理 - 控制闭环，自成体系；③独立性：专注行车指挥，与其他信息化系统并行；④实时性：信息捕捉 - 传输 - 显示无延迟，循环执行；⑤高可靠性：容错设计，设备冗余（双服务器 / 双交换机）；⑥安全性：故障 - 安全，防非法入侵 / 病毒，数据备份；⑦可用性：故障自动切换，支持接口兼容；⑧操作简便：友好人机界面，软件实用。
  2. DMIS 各层之间的通信方式答：三级网络通过 “局域网 + 广域网” 互连：①铁道部 - 铁路局：专用数字通道（如 DDN），路由器互连，TCP/IP 协议，传输全路实时信息；②铁路局 - 站段：专用数字通道（2M），路由器互连，传输局内调度命令 / 运行图数据；③站段 - 基层网：2M 数字通道或 V.35 接口，传输采集的列车到发 / 信号状态信息，采用 HDLC 协议保障可靠传输。
  3. DMIS 系统的功能作用答：核心是实现行车调度自动化，具体：①实时监视列车运行（位置 / 信号状态）；②自动统计正点率 / 密度，支撑宏观决策；③自动绘制运行图，替代人工画图；④调度命令数字化下达，提高效率；⑤车次号自动跟踪 + 校核，减少人工误差；⑥站间透明显示，帮助车站值班员提前准备接发车；⑦历史数据存储，支持事故分析 / 工作总结。
  4. 计算机辅助行车调度系统（CAD）主要功能答：①实际运行图管理：存储 / 显示 / 查询 / 打印历史实际运行图，人工补录故障时的列车到发信息；②列车运行调整：自动铺划 4h 货运 / 8h 客运计划，支持人工手动调整，提供计划与实际对比；③运行统计：计算列车正晚点时分、平均速度（旅行 / 技术速度），生成统计报表；④共享动态数据库：存储车次跟踪 / 邻区段协调数据，支撑多区段协同调度。
  5. 调度监督与调度集中系统主要功能答：①显示功能：列车运行位置、信号机状态、道岔位置、股道占用情况；②车次跟踪：自动 / 人工关联车次与列车位置；③行车计划：接收 / 显示日班计划 / 阶段计划；④控制功能：人工（实时命令）、存储（预存命令序列）、自动（按计划）办理进路，支持站控 / 遥控切换；⑤维护功能：设备状态监测、故障告警、历史状态回放；⑥接口功能：与 DMIS/TMIS 系统交互数据。
  6. 调度监督与调度集中系统控制方式特点及原理答：
    • 人工控制：特点是实时性强、无排队，适合特殊情况；原理是调度员手动输入命令，系统立即检查联锁条件（无敌对进路 / 信号），满足则执行，不满足则告警。
    • 存储控制：特点是自动化程度高，适合车流稳定场景；原理是调度员预存命令序列，系统按顺序模拟执行（假锁闭），检查时机（无干扰），满足则执行，不满足则等待。
    • 自动控制：特点是完全依赖计划，效率最高；原理是计划系统按阶段计划生成进路命令，系统转换命令后检查时机，自动执行，无需人工干预。
    • 站控 / 遥控：特点是权限可切换，灵活适配现场需求；原理是车站申请站控时，调度员授权后，车站值班员通过控制台控制；调度员需遥控时，车站授权后，调度员通过 CTC 控制，二者互斥。

第六章 铁路综合数字移动通信系统（GSM-R）

一、核心内容总结

1. GSM-R 发展概述

  • 背景：铁路提速（120-250km/h）、客运专线建设需求，替代模拟无线列调（单信道、干扰大、难支持数据业务）。
  • 定义：基于 GSM Phase 2+，增加调度功能（VGCS/VBS/eMLPP），适配高速环境，国际铁路联盟（UIC）推荐的铁路专用移动通信系统。
  • 发展历程：
    1. 标准制定（1993-1995）：UIC 与 ETSI 合作，将铁路调度需求纳入 GSM Phase 2+。
    2. 试验阶段（1997-2000）：法 / 德 / 意高速线测试，验证可靠性 / 兼容性。
    3. 工程实施（1999 - 至今）：瑞典 Oresund 大桥首建商用网，德 / 瑞 / 西等国推广，我国 2000 年确定以 GSM-R 为铁路移动通信方向。
  • 业务模型：GSM 业务（电信终端 / 承载）+ 语音调度业务（eMLPP/VGCS/VBS）+ 铁路应用（功能寻址 / 位置寻址 / 列车控制）。

2. 铁路数字移动通信原理

  • 覆盖方式：
    • 面状覆盖：正六边形小区，频率复用（簇大小 N=i²+ij+j²，如 N=3/4/7），适用于站场 / 枢纽。
    • 线状覆盖（铁路专用）：圆形小区，沿铁路按 2/3/4 小区一组复用频率，重叠区宽度按 C/I≥9dB 设计，保障高速列车切换不中断。
  • 无线信道特性：
    • 传播损耗：自由空间损耗（PL=32.4+20lgd+20lgf）、多径衰落（瑞利衰落，用分集接收 / 均衡克服）。
    • 干扰：同频干扰（用定向天线 / 优化复用距离）、邻道干扰（用滤波器 / 合理信道分配）。
  • 传输技术：
    • 调制：GMSK（高斯滤波最小移频键控），BT=0.3，速率 270.833kbit/s，频谱效率高。
    • 分集接收：空间分集（多天线，间隔半波长）、频率分集（多载波）、时间分集（块交织），提高接收信噪比。
    • 信道均衡：自适应均衡器（横向 / 判决反馈），克服多径导致的码间干扰（ISI）。
    • 不连续传输（DTX）：话音激活时 13kbit/s，非激活时 500bit/s（传舒适噪声参数），降低干扰 / 节省功耗。
  • 信息处理：
    • 话音编码：RPE-LTP（规则脉冲激励长期预测），13kbit/s，MOS 分 3.5+，平衡质量与速率。
    • 加密：A5 算法生成伪随机序列，与信息比特异或，保障无线传输安全。

3. GSM-R 业务

  • 承载业务：无限制数据（UDI）、3.1kHz 音频、分组组装 / 分拆（PAD）、分组业务，支撑低层（1-3 层）信号传输。
  • 终端业务：
    • 语音：电话、紧急呼叫（无需 IMSI，优先级最高）。
    • 短消息：点对点（MO/PP/MT/PP，160 字符）、小区广播（93 字符，无确认）。
    • 传真：3 类传真（语音 / 传真交替、自动传真）。
    • 调度业务：VGCS（语音组呼，半双工，组内单用户讲话）、VBS（语音广播，仅主叫讲话）。
  • 补充业务：
    • eMLPP（增强多优先级与强拆，7 级优先级，高优先级可强拆低优先级）。
    • 号码识别：CLIP（主叫显示）、CLIR（主叫限制）、CoLP（被叫显示）、CoLR（被叫限制）。
    • 呼叫转移：无条件 / 遇忙 / 无应答 / 不可达前转。
    • 铁路特定业务：功能寻址（按功能号呼叫，如 “司机” 而非终端号）、基于位置的寻址（按列车位置路由至对应调度员）、铁路紧急呼叫（停止指定区域铁路活动）。

4. GSM-R 网络结构和功能

  • 网络子系统（NSS）：
    • MSC（移动交换中心）：核心，处理呼叫 / 切换 / 位置更新，含 GMSC（网关 MSC，路由查询）。
    • HLR（归属位置寄存器）：存储用户静态数据（IMSI/MSISDN/ 业务权限）。
    • VLR（拜访位置寄存器）：存储漫游用户动态数据（TMSI / 位置区）。
    • AuC（鉴权中心）：生成鉴权三参数组（RAND/SRES/Kc），保障用户身份合法。
    • EIR（设备识别寄存器）：存储 IMEI，分黑白灰名单，禁止非法设备接入。
    • GCR（组呼寄存器）：存储 VGCS/VBS 组 ID / 小区列表，支撑调度组呼。
  • 基站子系统（BSS）：
    • BTS（基站收发信机）：与 MS 通信，负责调制 / 解调 / 功率控制，含 TRX（收发信机，管理 1 个 TDMA 帧 8 个信道）、BCF（基站控制功能，Abis 接口管理）。
    • BSC（基站控制器）：管理多个 BTS，负责无线资源分配（信道 / 功率）、切换控制、业务集中。
    • TRAU（速率适配单元）：13kbit/s→64kbit/s PCM，适配固定网速率。
  • 操作维护子系统（OSS）：OMC-R（管理 BSS）、OMC-S（管理 NSS），实现配置 / 性能 / 故障 / 安全管理。
  • 接口协议：
    • Um 接口（MS-BTS）：GMSK 调制，LAPDm 协议（第二层），RR/MM/CM 子层（第三层）。
    • Abis 接口（BTS-BSC）：PCM 传输，LAPD 协议，支持无线信令 / OML 链路。
    • A 接口（BSC-MSC）：2M PCM，No.7 信令（MAP 协议），传递呼叫 / 位置更新信令。

5. GSM-R 识别码和寻址

  • 核心识别码：
    • IMSI（国际移动用户识别码）：MCC（国家码，中国 460）+MNC（网络码）+MSIN（用户识别），全球唯一。
    • MSISDN（移动用户 ISDN 号码）：CC（国家码）+NDC（国内目的地码）+SN（用户号码），对外拨号用。
    • IMEI（国际移动设备识别码）：TAC（型号批准码）+FAC（工厂码）+SNR（序列号）+SP（备用），标识设备合法性。
    • LAI（位置区识别码）：MCC+MNC+LAC（位置区码），用于位置更新。
  • 寻址方式：
    • 功能寻址：按功能号（如 “XX 次列车司机”）呼叫，通过 HLR 关联功能号与终端，实现功能与终端解耦。
    • 基于位置的寻址：按 MS 当前位置（小区 / 轨道电路）路由呼叫，如司机呼叫→当前区段调度员，需外部位置信息（GPS / 轨道电路）支撑。

二、课后题答案（复习思考题）

（注：原文档第六章复习思考题未完全列出，以下为核心题目及答案）

  1. GSM-R 与传统模拟无线列调的差异答：①技术体制：GSM-R 是数字系统，基于 GSM Phase 2+，支持多业务；模拟列调是单信道模拟系统，仅支持语音。②业务能力：GSM-R 支持语音 / 数据 / 短消息 / VGCS/VBS，模拟列调仅支持简单调度语音。③抗干扰：GSM-R 用数字调制 / 加密 / 分集，干扰小；模拟列调同频干扰严重。④兼容性：GSM-R 支持跨国 / 高速列车，模拟列调无兼容性。⑤扩展性：GSM-R 可平滑升级至 UMTS，模拟列调无扩展空间。
  2. GSM-R 中 GMSK 调制的特点答：①高斯滤波：BT=0.3，频谱滚降快，邻道干扰小；②恒包络：可使用高效率 C 类功放，降低设备功耗 / 体积；③速率：270.833kbit/s，适配 GSM 帧结构（每帧 8 时隙，每时隙 156.25bit）；④解调简单：无需线性功放，硬件实现成本低，适合移动终端。
  3. VGCS 与 VBS 的区别答：①讲话权限：VGCS 中组内用户可申请讲话（同一时间仅 1 人）；VBS 中仅主叫可讲话，组内用户无讲话权限。②业务场景：VGCS 用于调度协作（如司机 - 调度员 - 车站值班员）；VBS 用于单向通知（如调度员向多列车广播指令）。③信令交互：VGCS 需处理用户讲话申请 / 释放；VBS 无需，仅主叫发送，用户接收。
  4. GSM-R 网络中 HLR 与 VLR 的作用及数据差异答：①HLR：归属位置寄存器，存储用户静态数据（IMSI/MSISDN/ 业务权限 /eMLPP 优先级 / VGCS 组 ID），永久保存，全球唯一；作用是提供用户归属信息，支撑漫游时的呼叫路由 / 业务授权。②VLR：拜访位置寄存器，存储用户动态数据（TMSI / 位置区 / 漫游号 MSRN / 临时鉴权参数），用户离开后删除；作用是支撑本地呼叫处理 / 位置更新 / 切换，减少 HLR 查询次数，提高效率。

第七章 GSM-R 在铁路无线通信中的应用

一、核心内容总结

1. 功能寻址

  • 定义：按用户 “功能角色”（如 “XX 次列车司机”“XX 站值班员”）而非终端号码呼叫，功能号与终端解耦，终端更换不影响功能呼叫。
  • 实现原理：①HLR 中存储 “功能号 - IMSI” 映射关系；②主叫拨打功能号→MSC 查询 HLR→获取对应 IMSI→路由至目标终端；③功能号可动态注册 / 注销（如司机换班时更新映射）。
  • 应用场景：调度员呼叫特定列车司机、车站值班员呼叫邻站值班员，无需记忆终端号码，适配铁路人员流动性强的特点。

2. 基于位置的寻址

  • 定义：根据 MS 当前位置（如所在小区、轨道区段），自动路由呼叫至 “与位置关联的目标”，无需人工选择被叫。
  • 实现方式：
    1. 基于小区的路由：MS 所在小区 ID→MSC 查询位置数据库→关联对应调度员 / 车站（如小区 1→XX 区段调度台）。
    2. 基于外部位置的路由：通过 GPS / 轨道电路 / 查询应答器获取 MS 精确位置→传递至 MSC→路由至对应目标（如列车在 K100+500→呼叫 K100 区段防护员）。
  • 应用场景：司机呼叫调度员（自动路由至当前区段调度台）、区间作业人员呼叫车站（自动路由至最近车站值班员），减少人工操作，提高应急响应速度。

3. 无线列调

  • 定位：GSM-R 替代传统模拟无线列调（A/B/C 制式），成为铁路无线调度核心，支持列车 - 调度员 - 车站 - 作业人员全场景通信。
  • 功能升级：
    • 语音调度：VGCS 组呼（司机 - 调度员 - 车站三方协作）、VBS 广播（调度员向多列车发布指令）。
    • 数据传输：无线车次号、列车尾部风压、轴温检测数据，替代模拟列调的数话同传（减少信道占用）。
    • 应急通信：铁路紧急呼叫（优先级最高，停止指定区域作业）、区间作业人员移动通信（替代区间通话柱）。
  • 优势：①多信道：克服模拟单信道干扰问题；②高速适配：支持 250km/h 以上列车，切换不中断；③多业务：语音 + 数据融合，支撑调度自动化。

4. 调度数据和旅客服务信息传输通道

  • 调度数据传输：
    • 内容：DMIS 数据（列车运行计划 / 调度命令）、CTCS 数据（列车控制信息，如 ETCS-2 级车地通信）、设备监控数据（信号 / 电力设备状态）。
    • 通道：利用 GSM-R 电路域（64kbit/s）或分组域（GPRS），保障实时性（时延＜100ms）、可靠性（误码率＜10⁻⁶）。
  • 旅客服务信息传输：
    • 内容：车内 WiFi、旅客信息显示（到站时间 / 车次）、票务查询 / 订餐服务。
    • 通道：GPRS/EDGE（分组域），支撑宽带数据传输，带宽按需分配，提升旅客体验。
  • 关键技术：QoS 保障（调度数据优先级高于旅客数据）、冗余通道（主备信道，断道后切换）、安全加密（防止数据篡改 / 泄露）。

二、课后题答案（复习思考题）

  1. 功能寻址在铁路中的应用价值答：①降低操作复杂度：调度员 / 司机无需记忆终端号码，仅需拨打功能号（如 “XX 次司机”），适配铁路人员流动性强的场景；②提高业务连续性：终端故障 / 更换时，仅需在 HLR 更新 “功能号 - IMSI” 映射，无需通知所有关联用户；③支撑灵活调度：临时调整功能角色（如替班司机）时，快速注册新功能号，不影响正常调度。
  2. 基于位置的寻址如何提升铁路调度效率答：①减少人工干预：司机 / 作业人员呼叫时，系统自动根据位置路由至对应调度员 / 车站，无需人工选择被叫，降低操作失误；②加快应急响应：事故 / 故障时，MS 自动上报位置并路由至最近应急人员，缩短呼叫建立时间；③适配动态场景：列车高速移动中，位置实时更新，确保呼叫始终路由至当前责任主体（如跨区段时自动切换调度台），避免错呼。
  3. GSM-R 无线列调相比传统模拟无线列调的优势答：①技术体制：数字系统，抗干扰能力强（同频干扰用定向天线 / 频率复用克服），模拟列调单信道易受干扰；②业务能力：支持语音（VGCS/VBS）+ 数据（车次号 / 风压）融合，模拟列调仅支持简单语音；③高速适配：支持 250km/h 以上列车，切换成功率＞99.9%，模拟列调在高速下通信中断；④扩展性：可平滑升级至 GPRS/UMTS，支撑未来 CTCS-3 级列车控制，模拟列调无扩展空间。
  4. GSM-R 如何保障调度数据传输的可靠性答：①通道冗余：采用主备 2M 数字通道，断道后自动切换，无中断；②QoS 保障：调度数据（如 CTCS 指令）优先级设为最高，抢占低优先级业务（如旅客 WiFi）资源；③差错控制：采用前向纠错（FEC）+ 自动重传（ARQ），误码率＜10⁻⁶；④安全加密：A5 算法加密无线传输，IPSec 加密分组域数据，防止数据篡改 / 泄露；⑤网络冗余：MSC/BSC 采用 1+1 热备份，基站采用自愈环组网，设备故障不影响整体传输。
